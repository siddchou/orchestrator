# Phase 3 UI — Edge Cases & Failure Modes

| # | Scenario | Current Behavior Without Fix | Required Handling | Severity |
|---|----------|------------------------------|-------------------|----------|
| 1 | **User draws a cycle** (A→B, B→C, C→A) | PUT request sent → backend may reject with validation error, or worse: infinite loop in DagExecutionEngine | `cycleDetector.wouldCreateCycle()` called before edge is created. If true: snackbar "Cannot create circular dependency: A → B → C → A", rubber-band line snaps back, no state change | High |
| 2 | **Orphan step** — node with zero edges in a multi-step job | Node renders but has no connection to the DAG; DagExecutionEngine may never execute it (no parent triggers it) | Allow orphans visually but show a warning badge on the node: "⚠ Not connected — this step will not run unless it has no dependencies". Root nodes (zero incoming edges) are implicitly triggered, so only flag nodes with zero incoming AND zero outgoing edges in a job with >1 step | Medium |
| 3 | **Delete a node that other nodes depend on** | Dependent nodes have stale `dependsOnStepId` references → backend returns 404 on reload or execution fails | On delete: scan all other steps' dependencies for references to the deleted stepId. Show confirmation dialog listing affected steps. After deletion, remove those dependency edges from local state before saving. Backend DELETE step endpoint should cascade-delete dependencies (verify this; if not, explicitly clean up via PUT) | High |
| 4 | **Canvas renders a job with 50+ steps** | Auto-layout spreads nodes across a very wide canvas (>3000px). Edge paths cross densely. Performance degrades with O(n²) edge rendering | Layout: wrap nodes into columns of max 8 per layer. Canvas: virtualize — only render SVG paths for edges where both endpoints are within viewport ±100px. Pan/zoom remains full but edge path computation is lazy. Fit-to-view button essential | Medium |
| 5 | **User navigates away mid-edit with unsaved edge changes** | Changes lost silently; no warning | Integrate with existing `FormGuardService`: mark dirty on any edge add/remove/condition-change. Browser beforeunload handler + Angular route guard both trigger "Leave without saving?" confirmation | High |
| 6 | **Run-view canvas loses connection mid-run** (poll fails) | Canvas shows stale status; user doesn't know data is outdated | On poll failure: show a banner at top of canvas "Last updated: X minutes ago — click to refresh". Auto-retry poll. After 3 consecutive failures, stop polling and show manual refresh button | Medium |
| 7 | **Step type schema removed from backend** while job uses it | `iconFor()` returns fallback 'play_arrow'; step config form can't render | Same handling as existing StepFormDialog E5: show stepType label as-is with a warning chip. Canvas node shows the type name even without an icon mapping | Low |
| 8 | **Two users editing the same job's dependencies simultaneously** | Last save wins; one user's edges are silently overwritten | **[ASSUMED]** No real-time collaboration in Phase 3. Show "Last updated: X" timestamp in canvas toolbar. On save, include job `updatedAt` in request header; if server version is newer, show conflict dialog "This job was modified by another user. Reload?" | Medium |
| 9 | **Edge drawn from a step to itself** (self-loop) | Backend may accept it → execution deadlock | Validate before creation: `if (sourceStepId === targetStepId)` → snackbar "A step cannot depend on itself", abort | High |
| 10 | **Duplicate edge** — same source→target pair drawn twice | PUT sends duplicate dependency array entry → backend may create duplicate row or reject | Before adding, check if an edge already exists between this pair (regardless of condition). If so: open the condition picker to EDIT the existing edge instead of creating a new one | Medium |
| 11 | **Canvas viewport too small** — node ports overlap on narrow screens | Edge creation becomes impossible on mobile/tablet | Minimum canvas width: 600px. Below that, show a message "Switch to list view for smaller screens" with a button. Canvas view hidden below 600px breakpoint, list view shown instead | Low |
| 12 | **Job has steps but dependency API returns 404** (backend bug or migration gap) | Canvas shows nodes with no edges; user can't understand workflow | Catch 404 on dependency fetch: show snackbar "Could not load dependencies for step X — using step order as fallback". Fall back to rendering a linear chain based on `stepOrder` field | Medium |
| 13 | **Run-view canvas receives step status update for unknown stepId** | JavaScript error accessing undefined node model | Defensive check: `if (!nodeModel) return;` before updating status. Log warning with the unknown stepId | Low |
| 14 | **User drags a node so far it overlaps another node's ports** | Edge creation targets wrong port visually | Port hit detection uses actual DOM element coordinates, not visual position. Even if nodes overlap, `element.fromPoint(x,y)` resolves to the topmost element. Additionally, highlight the target node's entire border on port hover for clarity | Low |
| 15 | **SSE log-stream disconnects while run-view canvas is active** | Log viewer stops updating; canvas status still polls correctly | These are independent: log-stream SSE and status polling are separate connections. Canvas continues to work. Only the log viewer below is affected (existing behavior) | Low |
| 16 | **Edge condition picker renders off-screen** near canvas edge | Picker dropdown clipped by container overflow:hidden | Before positioning, check if picker bounds exceed canvas viewport. If so, flip position above/below the edge midpoint. Use a CDK portal/overlay for guaranteed positioning outside overflow containers | Medium |
